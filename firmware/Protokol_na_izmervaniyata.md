# Протокол на измерванията (за Глава 4)

**Средства:**

- **Мултиметър.** Запишете модела и обхватите — нужни са за оценката на грешката.
- **Вградените измервания във фърмуер v3:** `micros()`, броячи, CSV по UART.
- **Браузър** — телефон и компютър.
- **Програма за запис на серийния порт във файл.** Например PuTTY: Session → Logging → „All session output“, 115200 бода. Затворете Serial Monitor на Arduino IDE преди това — портът не може да се ползва от две програми едновременно.

**Правила:**

- Записвайте стойностите **точно както са показани**, с единиците.
- При всеки опит правете екранна снимка на картата „⏱️ Измервания“.
- Празна клетка е по-добра от предположение: в дипломната работа влизат само измерени стойности.
- Където не е посочено друго, преди опита изпълнете **`RESET STATS`** (или бутона „НУЛИРАЙ СТАТИСТИКАТА“).
- Не пишете в UART на **подчинения** модул по време на опитите за време — извеждането на текст удължава итерацията.

Изпратете ми: попълнените таблици (може и снимка на лист), CSV/лог файловете и снимките. От тях ще изчисля статистиките и ще начертая графиките.

## Е1. Време за цикъл на двата модула

**Цел:** реалното разпределение на времето за изпълнение и на периода на `loop()` и влиянието на уеб клиентите.

1. Главният модул е свързан към компютъра, записът във файл е пуснат. Въведете `LOG ON`.
2. **Режим А** — 10 min без отворен браузър.
3. **Режим Б** — 10 min с 1 отворен раздел на интерфейса.
4. **Режим В** — 10 min с 3 клиента едновременно (телефон, компютър и още едно устройство).
5. Отбелязвайте в лога с Enter, кога сменяте режима. Изпратете файла.

| Режим | Начален час | Краен час | Подчинен: „Итерации за 1 s“ | Главен: „Итерации за 1 s“ | Подчинен: макс. от старта | Бележка |
|---|---|---|---|---|---|---|
| А (0 клиента) | | | | | | |
| Б (1 клиент) | | | | | | |
| В (3 клиента) | | | | | | |

**По желание — сравнение с v2 по същия метод:**

1. Качете `v2_original/Master` на главния и `v2_izmervane/Slave` на подчинения модул (протокол v2).
2. Запишете 10 min от UART на **подчинения** модул — редове `V2LOOP,<ср. µs>,<макс. µs>,<итерации>,<ms>`. Направете и снимка на панела на v2 с „0 ms“.
3. Върнете v3 на двата модула.

(Реле 4 при v2 няма да работи, защото е преместено на D8. Това не влияе на измерването.)

## Е2. Причина за максималното време — четенето на DHT11

С `LOG ON` на главния модул:

1. `SET INTERVAL 500`, `SAVE`, `PUSH` → 5 min.
2. `SET INTERVAL 5000`, `SAVE`, `PUSH` → 5 min.
3. Върнете `SET INTERVAL 2000`, `SAVE`, `PUSH`.

При 500 ms DHT11 се чете само във всеки 4-ти прозорец, затова максимумът трябва да се появява през прозорец. Резултатът се вижда от лога — таблица не е нужна.

- **U_VIN** — между VIN и GND **на платката на подчинения модул**;
- **U_мод** — между VCC и GND **на модула на реле 4** (най-отдалечения);

## Е6. Бутони и програмният филтър срещу трептене

1. `RESET STATS`. Натиснете **D5 точно 50 пъти** с нормална скорост.
2. Запишете от „Бутон D5: натиск. / фронтове / макс.“.
3. Повторете за **D6** — той изключва всички релета, това е нормално.
4. Направете 20 **много кратки** почуквания на D5, колкото може по-бързо, и запишете колко са приети.

| Бутон | Натиснат, пъти | Приети натискания | Фронтове общо | Макс. фронтове за 1 превключване |
|---|---|---|---|---|
| D5 | 50 | | | |
| D6 | 50 | | | |
| D5, кратки почуквания | 20 | | | |

(Прекъсването може да не хване импулси, по-кратки от няколко µs — броят фронтове е долна граница.)

## Е8. Закъснение (PING) и потвърждение на ESP-NOW

Модулите са на 1–2 m един от друг, с пряка видимост. На главния модул има запис във файл.

1. `RESET STATS`, `PING 100`. Изчакайте „Край на теста“. Повторете 3 пъти.
2. Повторете още 1 път с 3 отворени уеб клиента.

| Серия | Условия | Успешни | Загубени | RTT мин. | RTT ср. | RTT макс. | ESP-NOW потвърждение мин./ср./макс. |
|---|---|---|---|---|---|---|---|
| 1 | 1–2 m | | | | | | |
| 2 | 1–2 m | | | | | | |
| 3 | 1–2 m | | | | | | |
| 4 | 1–2 m, 3 клиента | | | | | | |

(RTT включва и времето, докато подчиненият модул завърши текущата итерация. Ако заявката попадне по време на четене на DHT11, RTT расте с ~25 ms. Затова се очакват две групи стойности — ще се види на хистограмата.)

## Снимки, които ще са нужни

1. Целият макет отгоре, добре осветен.
2. Отблизо:
   - NodeMCU на подчинения модул с надписите на изводите;
   - релейните модули с джъмпера H;
   - модулът HR202 с потенциометъра;
   - DHT11;
   - двата бутона;
   - делителят към A0.
3. Главният модул.
4. Екранни снимки на интерфейса на v3 — горната част, „📊 Диагностика“, „⏱️ Измервания“ и „⚙️ Конфигурация“.
5. Serial Monitor:
   - менюто `M` на двата модула;
   - `7` на главния;
   - `6` на подчинения;
   - резултат от `PING 100`.
